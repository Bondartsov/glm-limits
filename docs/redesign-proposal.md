# GLM Limits — предложение по редизайну

Документ описывает целевой вид расширения (попап) и трей-компаньона. Текущая версия
работает и устраивает по функциям; здесь — про то, как она может выглядеть
спокойнее, «вровень» и с меньшим количеством шума. Макет: [`mockup.html`](mockup.html)
(открыть в браузере, есть переключатель светлая/тёмная).

---

## 1. Принципы

1. **Один экран — одна мысль.** «Сколько осталось в сессии» — герой экрана.
   Неделя и MCP — компактные строки, а не равные блоки: они важны, но не главные.
2. **Цифра без интерпретации.** Крупный процент остатка, рядом мелким — израсходовано.
   Никаких процентов «израсходовано» как основной цифры.
3. **Цвет = состояние, а не украшение.** Цветом окрашен только уровень риска
   (зелёный → красный). Акцент (синий) — для интерфейсных элементов, не для данных.
4. **Тишина по умолчанию.** Никаких анимаций, градиентов, теней-«стекла».
   Один акцент, тонкие линии, много воздуха.
5. **Тот же язык в браузере и в трее.** Одна палитра, одна типографика, одна
   иерархия — чтобы переключение «глазами» не требовало привыкания заново.

## 2. Палитра

| Токен       | Светлая   | Тёмная    | Где                            |
| ----------- | --------- | --------- | ------------------------------ |
| `--canvas`  | `#F7F8F9` | `#101214` | фон окна                       |
| `--surface` | `#FFFFFF` | `#17191C` | карточки, шапка                |
| `--line`    | `#E7E9EC` | `#24272B` | разделители, рамки             |
| `--text`    | `#17191C` | `#ECEEF1` | основной текст                 |
| `--muted`   | `#71767D` | `#8B9098` | подписи, второстепенное        |
| `--accent`  | `#3E6E9C` | `#6E9BC4` | интерактив, активные состояния |
| `--ok`      | `#5E9E73` | `#6FA983` | <50% израсходовано             |
| `--warn`    | `#C9A24B` | `#D3B05E` | 50–75%                         |
| `--hot`     | `#C2854B` | `#CE9260` | 75–90%                         |
| `--risk`    | `#C25F58` | `#CC6C64` | ≥90%                           |

Текущая палитра (бежевая «глина» + тёплый акцент) заменяется на нейтрально-серую
с холодным синим акцентом: меньше «домашнего» уюта, больше «прибора».

---

## 3. Типографика

- Шрифт: системный стек (`-apple-system / Segoe UI / Roboto`), без веб-шрифтов.
- Цифры: `font-variant-numeric: tabular-nums` (отсчёт не «прыгает»).
- Шкала: 44/600 — герой; 15/600 — заголовки строк; 13/400 — подписи; 12/400 — служебное.
- Лейблы метрик — **без uppercase**: «Сессия (5 ч)» обычным регистром, разрядка
  убрана (uppercase + letter-spacing выглядит «технически», а не лаконично).

## 4. Расширение (попап, 360 px)

```
┌────────────────────────────────────────┐
│ ▮▮▮ GLM Limits          ↻  ⤡  📌  ⤢  ⚙│  ← шапка: марка + иконки
├────────────────────────────────────────┤
│ ● Онлайн · z.ai · max                   │  ← строка статуса (одна)
│                                        │
│ Сессия (5 ч)                           │
│  67%                                   │  ← герой, 44/600
│  израсходовано 33% · 1 086 / 28 000     │  ← абсолютные значения
│  ▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │  ← полоса
│  ▁▁▁▂▃▅▇▆▄▂▁▁▁▂▃▄▆█▇▅▃▂▁▁▁▁▂▃▄▆▇▆  │  ← активность по часам (ось 00–23)
│  сброс через 3 ч 52 м · 16:56           │
│                                        │
│ Неделя                     94% ▓▓▓▓▓░  │  ← компактная строка
│                         сброс 6 д 22 ч  │
│ MCP                        98% ▓▓▓▓▓  │  ← опционально
├────────────────────────────────────────┤
│ v0.6.0 · api.z.ai · обновлено 21.10.26 │  ← служебная строка
└────────────────────────────────────────┘
```

Изменения против текущего:

- **Герой-карточка сессии** вместо трёх равных блоков: неделя и MCP — строки
  в одну колонку (метка слева, значение и мини-полоса справа).
- **Абсолютные значения** в подписи («1 086 / 28 000») — видно масштаб, а не только процент.
- **График активности по часам**: 24 столбца со шкалой 00:00–23:00 (высота — сколько окна
  сожгли в этот час, текущий час подсвечен). Вместо «кривой без координат» видно конкретные
  часы работы; для недели остаётся спарклайн по времени.
- **Настройки — отдельным листом**: панель настрорий накладывается поверх контента
  (своя прокрутка), а не растягивает попап. Сейчас панель длинная и выталкивает
  всё, из-за чего нужен скролл всего попапа.
- **Статус-строка** одна: точка + «Онлайн» + хост + тариф (сейчас — три строки
  в разных местах).
- Иконки остаются, но становятся тоньше (1.6px) и всегда в одном размере.

## 5. Трей-компаньон

**Иконка в трее:** без изменений по смыслу — скруглённый квадрат с процентом
остатка и цветом по уровню; при ошибке — приглушённый серый вместо «—».

**Окно деталей (320×260):**

```
┌──────────────────────────────────┐
│ GLM Limits            v0.6.0     │
│ обновлено 21.10.2026 16:05       │
│                                  │
│   ◯  67%                         │  ← кольцо-прогресс вместо полосы
│       Сессия (5 ч)               │
│       сброс через 3 ч 52 м       │
│                                  │
│ Неделя                       94% │
│ MCP                          98% │
├──────────────────────────────────┤
│ api.z.ai · обновлено 16:20  ⟳    │
└──────────────────────────────────┘
```

- **Кольцо** вместо полосы: круг заполняется по мере расхода, центральная цифра —
  остаток. Читается быстрее, чем две полосы.
- Второстепенные метрики — строки без полос (процент + тонкий индикатор).
- Нижняя строка: хост, время последнего опроса, кнопка обновления (иконка).

**Меню трея** — без изменений по составу, но строки-данные (сессия/неделя/сброс)
выравниваются по колонкам и показывают тот же формат, что и окно.

---

## 6. Что остаётся как есть

- Логика и модель данных (окна, пороги, кэш, история) — редизайн их не трогает.
- Цветовые пороги 50/75/90% — те же, что в коде.
- Функции: бейдж, уведомления, PiP, окно/compact-режимы, автообновление.
- Иконка расширения в браузере (марка со столбиками) — она уже в духе новой сетки.

---

## 7. Порядок внедрения (если решаем делать)

1. Токены палитры и типографики в CSS-переменных (без изменения разметки) — 1 шаг.
2. Новая сетка попапа: герой-карточка + строки — 1 экран.
3. Настройки листом поверх контента (и решить, нужна ли прокрутка попапа).
4. Окно трея: кольцо + строки, единый стиль с попапом.
5. Микро-правки: статусы, пустые состояния, «ключ не задан».

Каждый шаг независим и проверяем глазами; логику не трогаем — значит, откат
в любой момент стоит одну команду в git.
